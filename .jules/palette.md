## 2024-03-09 - Accessibility of focusable dynamic pre elements
**Learning:** Dynamically generated `<pre>` elements with `tabindex="0"` in webviews should provide context for screen readers to explain why they are focusable (e.g., that they are scrollable text regions), instead of relying solely on implicit focus behavior. `aria-label` shouldn't be used as it replaces content. `title="Use arrow keys to scroll"` provides keyboard interaction context.
**Action:** Always add `title="Use arrow keys to scroll"` to dynamic focusable `<pre>` elements in HTML strings to ensure keyboard interaction context.
## 2024-05-15 - ARIA redundancy and scrollable region context in Webviews
**Learning:** Adding `aria-label` that exactly duplicates the visible text ("Accept suggestion X") is redundant for screen readers. Furthermore, mixing instructional text ("Click to insert this suggestion into your code") into `aria-label` makes the accessible name overly verbose. In dynamically generated webview `<pre>` elements made focusable via `tabindex="0"`, they lack semantic meaning and group context for screen reader navigation if not given a group role.
**Action:** In webview suggestions, rely on the element's natural text content for its accessible name, and shift supplementary instructions to `aria-description`. When making scrollable regions like `<pre>` focusable, apply `role="group"` and an `aria-label` (e.g. "Code suggestion") so screen readers announce it properly.
